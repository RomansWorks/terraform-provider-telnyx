# AGENTS.md

Instructions for coding agents working on terraform-provider-telnyx.

## What this repository is

A Terraform and OpenTofu provider for the Telnyx API v2, built with the Terraform
Plugin Framework in Go and published as `romansworks/telnyx`. The goal is full
coverage: every Telnyx API operation is either implemented or deliberately
classified as out of scope.

## Specs come first

All requirements live in OpenSpec (`openspec/`). Do not change provider behaviour
without an OpenSpec change that describes it.

- Current requirements: `openspec/specs/` (`openspec list --specs`).
- Work in progress: `openspec/changes/`.
- Workflows: `/opsx:explore`, `/opsx:propose`, `/opsx:apply`, `/opsx:archive`
  (Codex and other agents: the `openspec-*` skills in `.agents/skills/`).
- Upstream API updates use the `telnyx-sync` schema and the **telnyx-sync** skill.

## Keeping up with the Telnyx API

When asked to "run the Telnyx sync" or update to the latest API, follow
`.claude/skills/telnyx-sync/SKILL.md` (same file in `.agents/skills/`). In short:

1. `make sync` (or check out the `sync/telnyx-api` branch the daily workflow opened)
2. `openspec new change sync-telnyx-<date>-<sha7> --schema telnyx-sync`
3. `make api-diff CHANGE=<name> BASE=origin/main`
4. Propose: spec deltas and tasks that account for every item in the diff
5. Apply: overrides, `make generate`, tests, examples, changelog
6. `make check`, then `openspec archive <name> --yes`

## Where the API contract is

| Path | What | Edit? |
|---|---|---|
| `upstream/telnyx/spec3.json` | The Telnyx OpenAPI 3.1 spec, pinned. 8 MB: do not read it whole. | Never. `make upstream-fetch` only. |
| `upstream/telnyx/lock.json` | Upstream repo, commit and sha256 of the pinned spec. | Never by hand. |
| `upstream/telnyx/by-tag/<tag>.json` | One self-contained document per product area. Read these. | Generated by `make catalog`. |
| `catalog/resources.yaml` | Candidate resources with their lifecycle operations. | Generated by `make catalog`. |
| `catalog/coverage.yaml` | How every operation is handled. | Yes: buckets, `terraform` names, notes, `reviewed`. |
| `generator/overrides/<name>.yaml` | One file per resource: its operations and what the spec cannot say. | Yes. |
| `internal/provider/generated/` | Resource descriptors derived from the spec and overrides. | Generated by `make generate`. |
| `internal/provider/hooks_<name>.go` | Hand-written behaviour (uploads, waits, reshaping responses). | Yes. |
| `internal/engine/` | The one implementation of create, read, update, delete and import. | Yes, with engine tests. |

Operations are keyed `METHOD /path`, never by operationId, because the Telnyx spec
reuses operationIds on aliased paths.

## Conventions

- Resource and data source names: `telnyx_<noun>`, snake_case, using the names
  Telnyx shows in its portal. Attributes: snake_case; lists, sets and maps are
  plural; booleans are true when the feature is on; write-only secrets end `_wo`.
- API calls go through `internal/client` only. Do not add the telnyx-go SDK.
- Objects the API cannot delete: destroy removes them from state and warns.
- 404 on read means the object was deleted outside Terraform: remove it from state.
- Every user-visible change gets a changelog entry: `changie new`.
- Never break users in a minor release: deprecate, then remove in the next major.

## Commands

| Command | Does |
|---|---|
| `make check` | Build, unit tests, lock and coverage check, OpenSpec validation. Run before pushing. |
| `make test` | Unit tests only. |
| `make testacc` | Acceptance tests against a real account. Needs `TELNYX_API_KEY`; creates billable objects. |
| `make generate` | Regenerates resource descriptors (`cmd/codegen`) and provider docs. |
| `make sync` | `upstream-fetch` + `catalog`. |
| `make api-diff CHANGE=<name>` | Writes the API diff report into an OpenSpec change. |
| `make api-check-release` | Release gate: also requires every coverage entry to be reviewed. |

## Safety

- Never commit API keys. Acceptance tests read `TELNYX_API_KEY` from the environment.
- Acceptance tests must clean up after themselves and register sweepers.
- Do not hand-edit generated files; change their source and regenerate.
